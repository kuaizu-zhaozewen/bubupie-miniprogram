## 推广领券：只搜索关键词

消费者路径：商城顶部搜索推广关键词 → 校验通过后券到账 → “我的优惠券”查看 → 商品详情选购 → 购物袋抵扣并模拟购买。

| 演示关键词 | 对应来源 | 演示券值 |
| --- | --- | --- |
| 海风小店 | 代理A | 5元 |
| 巷口伙伴 | 个人代理B | 10元 |
| 湾月好礼 | 官方商城 | 5元 |

代理工作台展示、复制推广关键词，并提供商城搜索入口预览；不显示扫码或生成二维码按钮。消费者无需扫描，也无需自行生成码。

商品名称支持普通文本搜索；只有与已配置推广关键词精确匹配时才发券与更新归因，搜索普通商品或无结果不修改代理、不发券。前后空格去除，正式服务端统一规范大小写与唯一性。停用、过期或不存在的关键词不发券、不记录有效归因。

每人每天只领1张推广券，同日搜索B不会在A的5元券之外再拿10元券，也不会把已有券升级。券源与代理归属分别保存；最后一次有效代理关键词决定后续订单归属，历史订单不变，官方关键词不清除最近有效代理。有效性按北京时间当日结束计算。

历史scene/token解析仅为旧链接兼容，当前页面不提供扫描入口，历史QR图片不是当前推广交付物。正式API以keyword为主要入口，旧scene如需保留必须由后端映射至同一推广来源，不形成第二套领取名额。

## 优惠券中心与购物袋

pages/coupons/index从商城顶部、底部导航、购物袋和个人中心进入。按“可使用 / 已使用 / 已过期”分别展示，含金额、来源、有效期和使用状态。已使用优先归入已使用；未使用且到期归入已过期；过期券没有去使用按钮。重复搜索返回原券当前状态。

购物袋在bubupie_commerce_v1中按演示买家独立保存，不因页面返回丢失。详情加入、增减数量、移除、用券开关、报价与模拟订单统一引用utils/commerce.js。同一账号在商品详情与购物袋之间切换能看到同一份商品数量；切换演示买家不串袋。

确认订单后才核销券，取消不核销、不创建订单。确认期间账号、数量、归因、券或金额变化要求重新确认。模拟下单成功清空购物袋，订单保留；收货、售后期结束、佣金结算与退款演示入口保留在购物袋订单区。代理佣金仍按商品原价合计20%计算，不扣平台券。

## 聊天：双方头像与完整消息

湾月改用专门的正面大头照，84rpx圆形；不再缩放全身图充当头像。用户右侧始终显示默认圆形用户头像，并显示昵称（未填时为“我”）。每条消息有清晰的角色名、气泡和对应头像。

消息区独立scroll-view，flex剩余高度且min-height为0；外层固定视口，输入区不收缩且始终位于底部。长文本自动换行，完整内容可滚动阅读，发送后滚至新增回复。三个问题继续位于问好下方，按同一IP当日状态回复。生日保持2027-01-01。

网页预览转换器修正了误把.chat-page等类名改写为.chat-body的选择器转换问题；只把独立page选择器转换为body。预览还支持嵌套wx:for-item、Enter确认、消息滚动位置与视口高度，不再依赖整页超长截图来掩盖实际可见区域。

## 正式后端契约变更（待实现）

POST /v1/mall/entry-claims输入由scene优先改为keyword，要求登录、幂等键、服务端精确匹配有效推广配置；事务中更新有效归因并查询/发行每日推广券。GET /v1/mall/entry可提供关键词校验与来源信息，不能让客户端自行传入agentId、券额或佣金率。

推广配置建议：promotionId、keywordNormalized（唯一）、agentId可空、campaignId、status、validFrom、validUntil、ruleVersion。每日券唯一键继续覆盖整个推广券族：(accountId,promotionCouponFamily,Asia/Shanghai-date)，不按代理各发一张。

GET /v1/me/coupons返回当前账号全部或分页券状态：claimId、faceValueFen、sourceName、claimedAt、expiresAt、status、usedOrderId。购物袋若需跨设备应迁移为服务端账号购物袋；当前只在本机演示。正式支付、发券、模型、库存、收货物流与代理鉴权仍未接入，订单、券事务、支付验签及佣金账本约束沿用V3.5说明。
